## 第一章：需求阶段——先想清楚要什么（1:40-3:30）

### 1.1 起点：完全不知道怎么下手

（画面：展示 Excalidraw 规划图 - 截图1）

很多人一想到"做个人网站"，
第一反应就是去找模板、搜教程、看别人的网站。

我一开始也是这样。
但真正坐下来准备做的时候发现——
卡住的根本不是"不会建站"，
而是不知道自己有什么素材，
也不知道这些素材该怎么组织。

所以我做的第一件事，
不是打开任何工具，
而是打开 Claude，跟它聊了一个问题：

"我想做一个个人网站，
把我的 AI 能力和 vibe coding 案例包装出来，
但我不知道怎么入手，
你能帮我整理一下思路吗？"

### 1.2 Claude 帮我理清了三件事

（画面：Excalidraw 规划图特写）

Claude 回来的第一句话就很关键——
**AI 产出的质量，直接取决于你整理好的素材的质量和具体程度。**

它帮我拆成了三步：
1. 素材整理框架——先搞清楚要放什么内容
2. 找参考和竞品——确定大风格方向
3. 规划优先级——一期做什么，二期做什么

### 1.3 素材整理：案例卡片法

（画面：展示案例卡片法的 Excalidraw 图 - 截图2）

这是整个过程里最重要、也最容易被跳过的一步。

Claude 教了我一个方法叫"案例卡片法"——
每个项目用统一格式填 6 个字段：

1️⃣ 项目名 + 一句话定位
2️⃣ 我的角色——具体做了什么
3️⃣ 关键决策 2-3 条——**这是灵魂**
4️⃣ AI 工作流——用了什么工具、怎么拆任务
5️⃣ 可量化结果——数字最有说服力
6️⃣ 素材清单——截图、视频、demo 链接

这里要重点说"关键决策"。

简历写的是"做了什么"，
但作品集要展示的是"为什么这样做"。

比如我做过一款儿童英语 App，
界面风格有两个选择——3D 游戏风和暖色插画风。
游戏风看着更酷，但我选了插画风。

为什么？因为这个 App 的付费决策者是家长，不是小孩。
插画风传递"安全""可信"，
游戏风第一反应会让家长觉得"这是在让孩子玩游戏"。

**这一句话，比"我设计了 UI"含金量高 100 倍。**

### 1.4 个人定位：把形容词换成事实

（画面：展示第一版 vs 最终版定位文案对比）

除了项目，还要写一段个人定位。

我的第一版写的是这种话：
"经验丰富的设计师，擅长连接创意与技术"——
这种可以套在任何人身上的话，等于没说。

后来我把所有形容词换成事实：
"15 年 UX 产品设计师，11 年专注 ToB 软件，
2025 年开始独立用 AI 做产品，
一个人从需求到上架了一款 App。"

**有事实、有数字、有具体事件，
这才是让人记住你的定位。**

### 1.5 素材回收：翻你的"数字痕迹"

（画面：App Store Connect 后台数据截图）

素材整理完第一轮之后，
我发现很多内容是"凭印象写的"，数据记不清。

这时候要做一件事：回去翻你的数字痕迹。

我翻了 App Store 后台，找到一组完整的转化链路：
6,493 次展示 → 688 次详情页查看 → 85 次下载 → 99 笔付费。

又翻了 GitHub，发现一个之前根本没注意过的仓库——
14 颗 star，4 个 fork。
这意味着已经有陌生人觉得这东西有用，主动用了。

**这些真实数据放在网站上，
比任何"我做了一个很棒的产品"都有说服力。**

## 第二章：设计阶段——先出图，再写代码（3:30-6:00）

### 2.1 收集灵感，提炼设计语言

（画面：设计灵感板 - 截图4）

素材整理完，下一步不是直接让 AI 生成网站，
而是先确定视觉方向。

我在 Pinterest、Dribbble、各种独立开发者网站上
收集了几十张参考图，提炼出 7 条设计语言：

1. 整体颜色低饱和色调
2. 用贴纸元素、动画点缀
3. 用像素、数字展现 AI 语言
4. 各种元素悬浮飘动，体现自然
5. 纸张吊牌卡片风格
6. 浅紫渐变
7. 手写标题

这不是随便选的"好看的风格"，
是根据我的定位（设计师 + AI + 专业但有温度）
筛选出来的。

### 2.2 用 Claude Design 出草图

（画面：5 个 Claude Design 方案对比 - 截图5）

有了设计语言之后，
我把素材和风格关键词喂给 Claude Design，
让它输出设计稿。

一共迭代了 5 个版本：

第一版：深色科技风——太冷了，不像设计师
第二版：浅紫白——结构定下来了，配色改对了
第三版：暖橙色证件卡风——加入了人物照片和悬挂卡片
第四版：手写签名 + 印章——更有个人辨识度
第五版：把三四版合并——最终定稿

（画面：最终定稿特写 - 橙色证件卡首屏）

**关键经验：迭代的时候不要推倒重来，
而是"锁定结构，只改变量"——
告诉 AI"保持这个布局，只改配色"，
比每次重新描述一遍高效 10 倍。**

### 2.3 为什么要先出设计图

如果跳过这步，直接让 AI 生成代码，
出来的东西会很"模板化"——
看着还行，但没有"你"的影子。

设计图相当于给 AI 一个"视觉锚点"，
有了它，Claude Code 的还原准确率会高很多。

## 第三章：技术选型——不是越复杂越好（6:00-8:30）

### 3.1 需求倒推技术栈

（画面：技术架构图）

到这一步，很多教程会直接说
"用 Next.js + Tailwind"，但没告诉你为什么。

我的选型逻辑是从需求倒推的：

需求1：网站要好看，有动画 → Next.js + Tailwind + Framer Motion
需求2：我要能随时添加新项目 → 需要后台管理 + 数据库
需求3：部署要简单，最好免费 → Cloudflare

所以最终技术栈：
前端：Next.js 15 + TypeScript + Tailwind CSS + Framer Motion
数据库：Cloudflare D1（SQLite）
部署：Cloudflare Workers
后台：自建管理系统

### 3.2 一个关键决策：为什么选 Cloudflare D1

这里有个小故事。

一开始 Claude 建议我用 Supabase（PostgreSQL），
后来 Codex 分析了我的项目之后说——
你的网站已经在 Cloudflare 上了，
用 D1 可以保持全链路在一个生态里，
部署、数据库、CDN 都在一个后台管理，
排查问题更容易。

**这就是为什么我同时用两个 AI 工具——
Claude 负责宏观规划和内容梳理，
Codex 负责看代码、做技术判断。
它们各有擅长。**

### 3.3 架构从静态到动态的升级

（画面：截图7 - 架构对比图）

原来的网站是纯静态的——
所有项目数据直接写死在 page.tsx 文件里，
改一个字就要重新部署。

现在的架构是"静态前台 + 动态接口"：
前台页面从 D1 数据库读取数据，
后台管理系统可以随时添加、编辑、删除项目，
前台自动更新，不用改代码。

## 第四章：Vibe Coding 实战——分步执行（8:30-13:30）

### 4.1 第一步：建数据库

（画面：截图6 - Codex 执行第一步）

把整理好的提示词发给 Codex，让它：
- 创建 D1 数据库
- 建 projects 和 articles 两张表
- 把现有 6 个项目数据导入数据库

6 分钟完成，本地验证：
featured = 3，small = 3，数据全部正确。

### 4.2 遇到第一个坑：部署架构冲突

（画面：截图7 右侧 - peer dependency 问题）

但这里遇到了第一个问题——
Codex 告诉我 @cloudflare/next-on-pages
和 Next.js 15.5 有兼容性冲突，
意味着数据虽然在数据库里，
但前台的动态路由跑不起来。

怎么解决的？

我把 Codex 的报错结论发给 Claude，
Claude 帮我写了一条修复指令：
"先尝试 OpenNext + Workers 方案，
如果不行再退回 Pages Functions 纯接口方案。"

再发回给 Codex 执行——
最终用 OpenNext + Cloudflare Workers 方案跑通了。

（画面：截图8 - API 返回 6 条数据 + 线上部署成功）

**这个过程的关键是：
Claude 负责决策——告诉 Codex "做什么"和"为什么"，
Codex 负责执行——看代码、改代码、跑测试。
两个工具配合，效率最高。**

### 4.3 第二步：后台登录系统

（画面：截图9 - Claude 写提示词给 Codex）

接下来做后台登录。

我让 Claude 帮我写好了完整的提示词——
包括登录页面、密码验证、session cookie、
middleware 路由保护、退出登录——
然后直接复制到 Codex 里执行。

（画面：截图10 - Codex 执行结果 + Claude 确认）

6 分 7 秒，全部跑通：
- 未登录访问 /admin 会自动跳转到登录页
- 错误密码返回 401
- 正确密码写入 HttpOnly cookie
- D1 里会存 session 记录
- 退出登录会清除 cookie 和数据库记录

### 4.4 配置密码（唯一需要手动做的事）

（画面：截图11 - Cloudflare 环境变量配置）

整个过程只有一个地方需要手动操作：
去 Cloudflare 后台配置管理员密码。

路径：Workers & Pages → portfolio-site 
→ Settings → Variables and Secrets → Add secret

变量名：ADMIN_PASSWORD
类型：选 Secret，不是普通明文

这是安全考虑——密码不写在代码里，
只存在服务器环境变量中。

### 4.5 第三步：项目管理后台

（画面：截图12 - 登录页 + 后台首页）

登录成功后进入后台首页，
显示：已发布项目 6，草稿 0，已发布文章 0，草稿 0。

（画面：截图13 - 404 页面）

但这里遇到第二个坑——
点"项目管理"进去是 404。

为什么？因为第二步只做了登录和首页，
项目管理的页面还是占位符。

解决方法很简单：
继续发第三步指令给 Codex——
做完整的项目列表页、新建/编辑页、
和前台动态化。

（画面：截图15 - Codex 执行第三步全过程）

这一步执行时间比较长，
因为它要同时改后台页面、API 接口、
和前台首页的数据源。

最终效果：

（画面：截图16 - 项目列表 + 新建项目表单）

后台项目列表：
有封面缩略图、标题、类型、状态、排序、操作按钮，
可以一键编辑、删除、切换发布状态。

新建项目表单：
标题、Slug、类型、Eyebrow、描述、封面图、
标签、外链、数据指标（动态键值对）、排序权重。

### 4.6 封面图怎么上传

（画面：截图17 - 封面图解决方案）

做到这一步遇到一个实际问题——
封面图从哪来？

第一期的方案是最简单的：
不做上传功能，直接用 GitHub 当图床。

把截图上传到 GitHub 仓库，
右键复制图片地址，
粘贴到表单的"封面图 URL"字段。

后续升级可以接 Cloudflare R2，
在后台直接上传图片——
但第一期先跑通最重要。

### 4.7 前台效果验证

（画面：展示前台首页 - 项目卡片从数据库动态拉取）

在后台新建一个测试项目，
切回前台刷新——新项目出现了。

这意味着整个链路跑通了：
后台填内容 → 存入 D1 数据库 → 前台 API 拉取 → 页面渲染。

以后新增项目再也不用改代码了。

## 第五章：前端设计实现——证件卡动画（13:30-15:30）

### 5.1 首屏设计的多次迭代

（画面：截图5 - 5 个设计方案对比）

前面说过，设计稿迭代了 5 个版本。
最终确定的是这个证件卡悬挂风格——
中间一张卡片从顶部弹性落下，
底部有云层光影缓慢飘动，
右侧三个项目卡片依次滑入。

### 5.2 给 Claude Code 的动画提示词

把这个设计稿和动画需求写成一条完整的提示词：
- 证件卡从顶部 translateY(-120%) 弹性落下
- 落下后轻微左右摆动
- 底部多层半透明云雾做 CSS 动画
- 右侧卡片 stagger 延迟依次滑入

### 5.3 踩坑：Token 耗尽

（画面：截图 - Claude Code 90% token 用量）

这里踩了一个大坑——
动画需求太复杂，Claude Code 光读代码分析结构
就花了 28 分钟，还没开始改文件，
token 就快用完了。

解决方法：
用 /btw 命令问它"你改了哪些文件，还剩什么没做"，
发现它还没动过任何文件，只是在分析。

于是我直接让它停下来，
等 token 重置后新开一个对话，
开头加一句"不要再读代码分析了，直接改文件"——
这次效率高了很多。

**经验：给 AI 的任务越大，
它花在"理解"上的时间就越长。
任务要拆小，每次只改一个文件。**

## 第七章：复盘和总结（16:30-18:00）

### 7.1 整个项目用了哪些工具

（画面：工具矩阵图）

Claude：素材整理、个人定位、提示词编写、决策判断
Claude Design：设计稿生成、视觉迭代
ChatGPT：生成设计效果图、插画头像
Codex：代码开发、数据库搭建、部署
Cloudflare：D1 数据库 + Workers 部署 + 域名管理

### 7.2 时间花在了哪里

素材整理和定位：2 小时（最值得的 2 小时）
设计迭代：1.5 小时
数据库 + 后台开发：3-4 小时（分 4 步，每步不到 1 小时）
前端动画：2 小时（含踩坑时间）
部署和调试：30 分钟

总计大约 10 小时，分散在一周内完成。

### 7.3 这套方法普通人怎么复用

（画面：7 步行动清单）

如果你也想做一个这样的网站，按这个顺序：

第一步：写一句"事实版"自我介绍，去掉所有形容词
第二步：列出 3-5 个项目，每个填 6 字段卡片
第三步：翻你的数字痕迹——后台数据、GitHub、过去的文档
第四步：做取舍——不是所有素材都该放
第五步：先出设计图，锁定方向，迭代改变量不改结构
第六步：分步给 AI 指令——先视觉后内容，先架构后功能
第七步：最后打磨细节——一句签名，让网站有态度

### 7.4 核心观点

整个过程里，AI 做的只是最后的执行。
前面所有的判断——
放什么不放什么、选什么风格、
数据库用哪个、任务怎么拆——
全都得靠你自己。

而这个判断的能力，
恰恰是 AI 时代每个人最值得投资的东西。
