# Build Personal Portfolio Site

## 目标

帮助用户把自己的身份、经历、项目、故事、审美和成果，转化成一个清晰、有说服力、可上线的个人网站。

不要一开始就套模板或直接写代码。先理解用户是谁、想被谁看见、希望别人记住什么，再决定网站结构、文案、视觉和实现方式。

## 使用原则

- 先定位，再设计。
- 先内容叙事，再页面结构。
- 先首页可运行版本，再扩展详情页、文章、后台或部署。
- 不做空泛的“高级感”，要让用户的真实项目、经历和结果成为主角。
- 每次实现后，都要运行预览并检查桌面和移动端效果。

## 第一步：信息采集

不要一次问太多问题。优先每次问 3-5 个关键问题。

### 1. 个人定位

询问：

```text
1. 你是谁？你的职业、身份或领域是什么？
2. 你希望别人通过这个网站记住你什么？
3. 这个网站主要给谁看？招聘方、客户、合作方、粉丝、投资人，还是朋友？
```

需要得到：

- 用户身份
- 专业领域
- 个人标签
- 核心差异点
- 目标受众

### 2. 网站目标

询问：

```text
1. 你做这个网站的主要目的是什么？找工作、接单、展示作品、建立个人品牌、卖产品，还是记录成长？
2. 你希望访客看完网站后做什么？联系你、看作品、关注社媒、下载简历、体验产品，还是预约合作？
3. 你目前最想展示的是作品、个人故事、内容影响力，还是技术能力？
```

需要得到：

- 网站目标
- 第一行动按钮
- 第二行动按钮
- 首页重点
- 转化路径

### 3. 项目素材

询问：

```text
1. 你有哪些项目？每个项目的名字和一句话介绍是什么？
2. 你在项目中承担什么角色？
3. 有没有结果数据？例如用户数、下载量、展示次数、收入、GitHub Stars、客户数、转化率。
4. 有没有截图、视频、Demo、App Store 链接、GitHub 链接或文章链接？
```

需要得到：

- 项目清单
- 项目优先级
- 项目类型
- 项目结果
- 可展示素材

### 4. 个人故事

询问：

```text
1. 你的职业路径是怎样的？
2. 最近一次重要转变是什么？
3. 有没有一个最能代表你的关键词？例如 AI Builder、产品设计师、独立开发者、创作者、研究者。
```

需要得到：

- About 文案素材
- 个人转型故事
- 可信度来源
- 情绪基调

### 5. 视觉风格

询问：

```text
1. 你喜欢什么感觉？专业、温柔、极简、科技感、杂志感、可爱、暗黑、松弛、实验性？
2. 有没有喜欢的网站、截图、海报、App 或品牌参考？
3. 有没有不喜欢的风格？
```

需要得到：

- 色彩方向
- 字体气质
- 图片风格
- 动效强度
- 参考案例

### 6. 功能范围

询问：

```text
1. 你希望网站只是静态作品集，还是需要文章、项目详情页、后台管理、数据展示？
2. 你是否已有代码仓库？
3. 你准备部署在哪里？Cloudflare、Vercel、GitHub Pages，还是先本地预览？
```

需要得到：

- 技术范围
- 页面数量
- 是否需要后台
- 是否需要部署
- 是否基于现有项目修改

## 第二步：生成网站策略

根据用户回答，先输出一份简短的网站策略。

必须包含：

```text
1. 一句话定位
2. 目标受众
3. 网站目标
4. 首页叙事
5. 核心 CTA
6. 项目展示重点
7. 视觉方向
8. 当前缺失素材
```

示例结构：

```markdown
## 个人网站策略

### 一句话定位

你是一个将产品设计、AI 工具和独立开发结合起来的 AI Builder。

### 目标受众

- 招聘方
- 潜在合作方
- 关注 AI 产品实践的人

### 网站目标

让访客快速理解你是谁、你做过什么、你能交付什么，并引导他们查看作品或联系你。

### 首页叙事

1. 先用一句话建立身份
2. 用数据证明你不是只停留在想法
3. 用精选项目展示能力
4. 用 About 补充个人故事
5. 用社媒和联系入口完成转化
```

## 第三步：规划首页结构

推荐首页结构：

```text
1. Hero 首屏
2. 关键数据
3. 精选作品
4. 小产品 / 实验项目
5. 关于我
6. 内容 / Notes / 社交平台
7. 联系方式
```

### Hero 首屏

必须回答：

- 我是谁
- 我做什么
- 我有什么不同
- 访客下一步该点哪里

Hero 可以包含：

```text
姓名 / 品牌名
职业身份
一句话定位
主按钮
次按钮
头像 / 视频 / 代表性视觉
```

### 数据区

适合展示：

```text
工作年限
上线产品数
用户数
下载量
展示次数
收入
GitHub Stars
内容平台粉丝
服务客户数
```

### 精选作品

每个项目卡片建议包含：

```text
项目名
一句话说明
标签
封面图
角色
结果数据
详情链接
```

### 关于我

About 不要写成简历流水账。应写成：

```text
过去背景
现在定位
关键转变
正在做什么
为什么值得被信任
```

## 第四步：项目案例模板

每个项目建议整理为：

```markdown
# 项目名

## 一句话定位

这个项目是什么？为谁解决什么问题？

## 我的角色

我在项目中负责什么？

## 用户问题

用户为什么需要它？

## 关键决策

1. 决策一
2. 决策二
3. 决策三

## 工作流程

如果使用 AI 或特殊工具，需要说明：

- 用了什么工具
- 怎么拆任务
- 哪些部分由 AI 辅助
- 哪些部分由自己判断和验证

## 结果

使用可量化结果：

- 用户数
- 下载量
- 展示次数
- 收入
- 转化率
- GitHub Stars
- 客户反馈

## 素材

- 截图
- 视频
- Demo
- 链接
```

## 第五步：文案生成规则

文案要具体，不要空泛。

避免：

```text
热爱设计
追求极致
赋能用户
打造优秀体验
拥有丰富经验
```

优先：

```text
10 年 UX 产品设计经验
独立完成从需求、设计、开发到上架
无广告投放获得 99 位自然用户
用 AI 工作流把想法变成可运行产品
```

### 好的个人定位句

格式：

```text
我是谁 + 我用什么能力 + 为谁创造什么结果
```

示例：

```text
10 年 UX 产品设计师，用 AI 把想法快速变成可运行产品。
```

```text
独立开发者与 AI Builder，专注把个人想法做成真实上线的产品。
```

## 第六步：视觉设计规则

根据用户气质选择视觉方向。

### 专业型作品集

适合：

- 克制配色
- 清晰信息层级
- 大量真实截图
- 少量动效
- 高可读性

避免：

- 过度装饰
- 太多渐变
- 假插画
- 空泛科技感

### 创作者 / AI Builder 网站

适合：

- 展示实验过程
- 展示工具链
- 展示项目截图
- 展示内容平台
- 适当加入动效和个人风格

### 产品设计师网站

适合：

- 项目卡片清晰
- 过程和结果并重
- 截图质量高
- 数据和设计判断并重

### 独立开发者网站

适合：

- 上线产品
- GitHub / App Store / Demo 链接
- 技术栈
- 用户结果
- 构建过程

## 第七步：实现流程

如果用户已有代码仓库：

```text
1. 先读取项目结构
2. 判断技术栈
3. 找到首页文件、样式文件、数据文件
4. 只做和需求相关的修改
5. 运行构建
6. 启动本地预览
7. 截图检查桌面和移动端
8. 给出预览链接和修改说明
```

如果从零创建：

```text
1. 选择合适技术栈
2. 先做首页
3. 再做项目数据结构
4. 再做响应式
5. 再做项目详情页
6. 最后部署
```

## 第八步：质量检查

完成后必须检查：

```text
1. 首屏是否立刻说明用户是谁
2. 主标题是否具体
3. CTA 是否清楚
4. 项目是否有真实结果
5. 移动端是否能读
6. 图片是否变形
7. 文字是否溢出
8. 动效是否遮挡内容
9. 构建是否通过
10. 是否有可访问的预览链接
```

## 第九步：输出格式

根据用户当前阶段输出不同内容。

### 用户还没想清楚时

输出：

```text
定位问题
内容清单
网站结构建议
下一步采集素材
```

### 用户有素材但没有网站时

输出：

```text
网站策略
首页文案
项目卡片内容
视觉方向
开发 Prompt
```

### 用户已有网站时

输出：

```text
问题诊断
修改建议
直接改代码
本地预览
构建验证
```

### 用户要部署时

输出：

```text
构建结果
部署地址
版本信息
注意事项
```

## 第十步：普通用户使用示例

用户可以这样说：

```text
我想做一个个人网站。我是产品设计师，有 3 个项目，希望展示作品和个人品牌。
```

```text
帮我把这些项目资料整理成个人作品集网站结构。
```

```text
我有一个现有网站，帮我改成更适合 AI Builder 的个人主页。
```

```text
帮我生成首页文案、项目卡片和 About 页面。
```

```text
帮我把这个作品集网站部署到 Cloudflare。
```

## 第十一步：默认交付物

如果用户没有特别指定，默认交付：

```text
1. 个人网站定位
2. 首页结构
3. 首页文案
4. 项目展示模板
5. About 文案
6. 视觉风格建议
7. 素材缺口清单
8. 下一步实现建议
```

如果用户要求实现，则交付：

```text
1. 可运行网站
2. 修改文件说明
3. 本地预览地址
4. 构建验证结果
5. 部署地址，如果用户要求部署
```

## 注意事项

- 不要把网站做成普通模板。
- 不要只写漂亮形容词，要写具体事实。
- 不要让动效压过内容。
- 不要在没有素材时假装项目很完整。
- 不要过早引入复杂后台。
- 不要忽略移动端。
- 不要替用户编造数据。
- 如果数据不足，明确标注“待补充”。
